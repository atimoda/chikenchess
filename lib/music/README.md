# Strudel music engine and Creative lab

Current release: v0.14.2 — 03/10/2026. All 46 stages (34 cities) and Creative use `@strudel/web` 1.3.0. Instruments store explicit MIDI rolls and shared global arrangements in schema v7; Strudel remains the playback and generated-code backend. The existing native engine continues to provide introductory/UI/end-game sound effects; its loop compilation and playback are disabled for these stages.

For task-oriented navigation, start with `docs/CODEBASE_MAP.md` and `tests/README.md`.

## Try it

Run `npm install` and `npm run dev`, then open `/?city=dusseldorf` on the printed local URL. Complete the existing introduction.

For immediate experiments, open `/creative`, choose a factory or saved kit and press **Carregar kit**. Current-revision saved city kits take priority over composed factory arrangements; an incompatible catalog revision falls back to the bundled MIDI kit. The 16 white voices are active in Creative; gameplay activation still comes from moves and the temporary check overlay. **Salvar kit** stores the edited kit in this browser and can link it to one city at a time. Export JSON to transfer kits between devices; there is no shared database yet. The historical one-time MIDI v5 reset and the preserving v6 migration are distinguished below.

- Hold/drag a piece to play individual notes before making a move. Its loop is suspended during the gesture; entering a new square triggers one attack. Holding still does not repeat the phrase. Solo plays the complete pattern; multiple Solo voices can be combined, and the voices that were playing before the first Solo return when the last one is disabled. The redundant hold-to-listen button was removed.
- Release on an illegal destination, the original square, or outside the board to cancel. Escape, touch cancellation, and window blur also end the audition.
- Complete a legal move to activate that piece's pattern. AI pieces activate on their moves too. Captured pieces are removed from playback.
- Check temporarily activates all surviving attacker pieces; authored rests and per-piece arrangement absences still apply. Resolving check restores history-based activation. This overlay never records an unmoved piece as moved. Checkmate/pausing stops the transport as before.
- Select a piece to inspect its instrument and adjust gain, pitch, pan, decay, filters, reverb, and delay. The inspector follows its identity after moves and stays selected when the AI moves.
- Piece Params contains note/rest feedback, a play-chance knob, and envelope/octave/gate controls. Board Params changes the shared root/scale. Strudel contains transport/status above the code. In-game edits stay local to that match; save city kits through Creative.

See `GAME_MECHANICS.md` for the maintained behavior inventory, gesture limitations and state priorities.
- The code widget is generated from the same voice specifications used to build the Strudel patterns. The spectrogram reads the new audio output.

## Modules

- `reactions.ts` (v0.3.2): validated per-kit state/event rules, deterministic history ledger and reversible audio overlays shared by Creative and gameplay. Factory and legacy unedited kits receive the versioned 26-rule preset; authored rule sets are preserved. Event durations use plies; per-rule bar scheduling and tempo ramps are owned by the audio transport. See GAME_MECHANICS.md for triggers, scope, priorities and the simulation's differences from match termination.
- `harmony.ts`: Kit Harmony uses saved global section degrees and written MIDI voicings, falling back to root 0. Other named plans ignore section degrees without deleting them, using their own centers/voicings; Static remains a separate option. Global sections may store 1–8 scale degrees (−14 to +14), one per local bar, repeated as needed. `harmonic-pattern.ts` applies harmony at each original attack independently of bank length/phase, shared by compiler and generated export. Reactions temporarily replace the plan and restore it on expiry. Pulse voices, manual audition and unpitched samples do not follow these paths.
- `manchester-kit.ts`: loads the complete MIDI kit from `public/presets/manchester-1999.json`: curated Manchester 1999, 123 BPM / G Dorian, explicit MIDI banks with weighted 5:4 eighths and complementary motifs. The original four-scene form now includes E/F, yielding A4/B6/C3/D6/E4/F8. It uses the original `chicken-jazz-v1` one-shots plus new piano and ride colors. No reference audio is bundled. `node scripts/export-manchester-kit.cjs` reads that JSON source and regenerates only the Strudel score. Sample URLs in the score require this app's `/samples` directory on the serving origin.
- `team-mixer.ts`: two post-effects Web Audio buses with independent gain and three-band EQ. Match-only fine pitch changes the shared tempo and tuning; quartz lock restores loaded-kit BPM and normal tuning while preserving the prepared slider value. Reverse audio and scratching are not implemented.
- `voice-spec.ts` assigns loop voices to four Superdough effect orbits on desktop and two on constrained devices; temporary auditions keep isolated orbits. `runtime-session.ts` retains a shared orbit until its final loop voice leaves. Continuous performance forms use `pick` to query only the selected phase-preserving bank, while restarting forms use `pickRestart`.
- `runtime-session.ts` waits for `initAudio`/AudioWorklet readiness before playback or output that needs Drive/distortion or `controls.s === 'supersaw'`, including Düsseldorf original's first Play. Dry manual notes that need neither processor keep the immediate path. Awaiting a worklet never revives cancelled, hidden, disposed or expired notes.
- `model.ts`: stable piece identity reconstructed from legal move history, shared scale conversion, initial electronic instrument definitions.
- `runtime.ts`: compatible entry point. Implementations: `runtime-types.ts` (contracts), `voice-spec.ts` (resolved controls), `pattern-compiler.ts` (MIDI rolls compiled to Strudel patterns), `code-export.ts` (equivalent generated score), `pattern-inspection.ts` (MIDI validation), `strudel-loader.ts` (shared loading), `runtime-session.ts` (playback lifecycle). Internal modules import contracts directly, avoiding cycles through the facade.
- `sample-banks.ts`: source registry independent of chess roles and playback behavior; bank, asset, articulation and optional root-note tuning. Assets load only when needed and buffers are shared. Registered CC0 banks cover electronic, jazz and world sources, strings/guitars, keys, synths and percussion. Four generated timbre banks come from `python3 scripts/generate-timbre-samples.py`; the recorded Band/Percussion/Guitars banks are described in `recorded-banks.ts`. `kit-profiles/timbre-curation.ts` assigns selected voices in earlier phases, while `harmonic-stage-factory.ts` picks palettes and beats for the ten harmonic phases. Asset details and limitations are in `public/samples/README.md`.
- `creative.ts` and `city-kits.ts`: schema v7, bounded legacy imports, factory kits, import validation and browser-local persistence. Every instrument requires 1–8 explicit `PianoRoll` entries and assignments to every global section ID. Text notes/phrases, masks, groove bindings, automations and `pianoOnly` are absent. Source, behavior and chess role remain independent. Existing MIDI v5 storage keys are retained.
- `loop-ranges.ts` and `range-frequency.ts`: deterministic L/S/N ranges for octave, Drive, Reverb, Swing and LPF, plus a fixed single-value mode; compiler and generated code share the same event processing. N is the default frequency; deselecting L/S/N saves a fixed value. LPF spans 20–20000 Hz. An active LPF rule removes `lpfRange` from the resolved snapshot and supplies its fixed cutoff; expiry restores the base range.
- `random-kit.ts`: versioned seeded arrangements for every city, randomized roles and bounded parameters. This remains an experimental generator; factory defaults now come from styled-kits.ts.
- `monitor.ts` and `components/music-playback.tsx`: shared section/beat, custom `sectionLabel`, notes/rests and resolved controls. `runtime-session.ts` reports global section and local-bar harmony; absent sections remain rests under pins and rules. Queries use the compiled Strudel patterns aligned to the transport clock; small subscribers and per-cycle caches avoid rerendering the editor on every tick.
- Variation panels draw saved rolls directly, using `arrangement.ts`/`performance.ts` for shared position, phase and presence, and `pianoRolls.length` for actual bank count. They perform no async text conversion. `variation-edit.ts` adds an empty bank, removes the last bank and updates affected assignments/pins, mirrors timing or randomizes notes. Pins and rules choose only the bank; an absent global section stays absent. Only an enabled active loop with running transport has a playhead.
- `hooks/use-music.ts`: React state and controls. Piece parameter edits are keyed by identity; undo/redo restores board-derived activation and position while retaining manual edits.

## Checks

`npm run test:music` covers activation, audition rollback, captures, en passant, castling, history reconstruction, source independence, explicit MIDI timing, ranges, arrangements, schema migration, sample files, city persistence, playback feedback and transport races. Pattern tests import the same `@strudel/web/dist/index.mjs` ESM bundle used by the browser; only browser event-listener globals are stubbed. `npm run typecheck` checks application types. Consult `tests/README.md` for the maintained domain runners; passing patterns does not establish listening quality or physical-device performance.

The comparative Düsseldorf preset timeline is `[0@4 1@4 2@4 1@4]/16`: A/B/C/B, four cycles each. The former `<0@4 1@4 2@4 1@4>/16` unintentionally held each section for 64 cycles. Imports repair that exact legacy factory string; recognized numeric weighted timelines are migrated to bounded global sections; this does not preserve arbitrary text timelines. Düsseldorf original and Mouth Breather remain available as migrated MIDI presets.

## Schema v7 and local storage

The first MIDI-only delivery introduced a one-time reset: `resetLegacyMusicStorage()` removes `chickenchess:creative:v1`, `chickenchess:creative:v1:kits` and `chickenchess:city-kit:v1:*`, then writes `chickenchess:music:midi-v5`. Subsequent calls preserve newly saved kits. That historical reset discarded old music edits without recovery and did not touch profile/progress. Global arrangement migration adds no reset, marker or deletion: schema v7 continues using `chickenchess:creative:v5` and `chickenchess:creative:v5:kits`.

Imports from versions 1–4 preserve existing explicit rolls and use instrument defaults for missing banks, then pass through the v5 → v6 bridge. The first instrument with timed performance steps supplies global durations; pieces retain assignments by index, repeating shorter step lists if needed. With no timed performance, only the bounded numeric weighted legacy factory form supplies durations; the known Düsseldorf form is repaired first. Otherwise the fallback is A with four pulses. `harmonicSequences` becomes `section.harmony`; retired `performance` and `sectionPattern` are removed before playback. This bridge does not interpret old note phrases or restore the text engine. The parser keeps the 2,000,000-character JSON budget, 1–8 rolls and 128 notes per roll. Validation precedes replacing the session; source, behavior, pins, effects and mappings remain supported.

The v6 → v7 step selects Kit Harmony for files containing authored section degrees. Version 7 distinguishes that migration from an intentional named-plan override and preserves both the selected plan and saved degrees. Factory profiles with authored degrees also select Kit Harmony; no storage keys or catalog reset markers change.

## Deliberate scope of this prototype

The current editor combines explicit MIDI rolls, synths, registered samples, envelopes, effects and a global arrangement with per-piece assignments. Recipe/text-code editors, advanced text-form fields, shared Groove controls and automation editors have been removed, together with `automation.ts`, `grooves.ts` and `pattern-library.ts`. Strudel execution, inspection and generated export remain. Global sections have stable IDs, editable names/durations/order and optional harmonic paths; instruments reference these sections rather than saving independent durations/forms. Pins and rules replace only the MIDI bank, preserving section presence, transpose and restart. A stopped transport restarts from the beginning on resume; editing or deactivating loops while playing preserves its clock. Further harmonic extensions, cadence preparation, continuous legato, sample uploads and official publishing remain in MUSIC_ENGINE_PLAN.md. Full network-free application loading, listening quality and physical mobile performance remain unverified.

Strudel references: [samples](https://strudel.cc/learn/samples/), [effects](https://strudel.cc/learn/effects/), [mini-notation](https://strudel.cc/learn/mini-notation/).

- `scales.ts`: catálogo comum de escalas em 12-TET, utilizado pela sessão e pelas reações.
- `transport.ts` / `reaction-queue.ts`: audio-time scheduling, analytic BPM ramps, per-rule pending changes and cancellation. Creative section clicks queue a destination at the current section's unscheduled end; last choice wins before audio commitment. Lookahead schedules the destination downbeat at the exact old boundary time while the monitor retains its preceding tempo/section until that deadline. Current buses and tails are not cut. Pending rules rebase to the next destination bar, and ramps retain instantaneous BPM/remaining duration. Paused selection parks the next Play. Pause, hiding, kit/meter replacement and disposal cancel pending transitions; no queue is persisted. Immediate low-level seeks remain for parked positioning/tests. React only displays clock state.
- `piano-roll.ts`: bounded note/duration schema for independent explicit loops; both editors operate directly on these notes, without a text restoration source.

- `arrangement.ts`: schema and shared position for 1–24 sections, 0.25–64 pulses each, at most 512 total. Unique IDs are limited to 80 characters and labels to 40. Session storage is `arrangement.sections[{id,label,beats,harmony?}]`; instrument storage is `arrangement{restart,sections:{[globalId]:{variation,transpose,active}}}`. Reordering/renaming retains assignments by ID; new sections use index modulo each instrument's actual bank count. `creative.ts` validates every assignment against existing MIDI banks; no four-bank clamp remains.
- `performance.ts`: derived execution plans and editor phase/presence. Durations come from the global arrangement; `pickRestart` starts MIDI at section entry and `pick` preserves its phase. Rule override wins over a manual pin, which wins over the section's bank assignment; every choice retains global presence, chromatic transpose (−24 to +24 semitones) and restart. These derived plans are not independent persisted forms.
- `components/music-arrangement-controls.tsx`: Creative's global section names, durations, add/remove/reorder and harmonic degrees. `music-performance-controls.tsx` references those sections and exposes only available MIDI banks, transpose, presence and restart for the selected piece; independent-form controls and per-piece duration editing are gone. Manual board audition remains one base attack per entered square and does not alter the arrangement clock.
- `kit-profiles/*.ts`: editable score profiles by city/era; each assigns 16 mirrored roles, MIDI banks, timbre, mix and per-section presence. `catalog.ts` registers them. `styled-kits.ts` composes the current defaults and A–F arrangements; `city-kits.ts` loads compatible saved MIDI kits or the bundled default. Profile fields remain composer inputs, converted to global sections and per-ID assignments; earlier four-bank limits and recoverable catalog migrations are historical. References/limits live in `MUSIC_STYLE_REFERENCES.md`.
- `scripts/export-mouth-breather.cjs`: extracts the supplied study's exact note timing using real Strudel and builds a six-piece preset with local synthetic timbres. The entire form, guitar/bass pitches, drum onsets and exported score are regression-tested.
- `piano-roll.ts` also stores optional per-note pitch envelopes and pan. Envelope time becomes canonical `pattack`; per-note values retain their priority over instrument controls.
- `components/info-tip.tsx`: hover/focus/touch help portalled above scrolling columns. Escape/outside press dismisses; pressing help does not edit the associated control.

- `roll-optimizer.ts`: finite event lanes shared by compiler/exporter; `manual-reverb-cache.ts`: bounded impulse reuse with isolated effect nodes. Measurements and rejected substitutions: `docs/CPU_OPTIMIZATION.md`.

## Historical text-era behavior (through schema v4)

Earlier releases used `automation.ts` for bounded section patterns and sine/ramp curves sampled at attacks, `grooves.ts` for shared rhythm/accent lanes, and `pattern-library.ts` for reference recipes. Their editors could convert finite text windows to rolls and restore the original source; `pianoOnly` marked scores without that source. Those modules, fields and UI paths were removed in v0.11.0. The earlier recoverable catalog migration described in the project history does not apply to the authorized one-time MIDI v5 storage reset.
