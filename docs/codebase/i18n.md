# Idiomas (i18n)

O jogo mostra os textos em 8 idiomas: português (`pt`), inglês (`en`), espanhol (`es`), mandarim (`zh`), hindi (`hi`), japonês (`ja`), russo (`ru`) e francês (`fr`). Comportamento para quem joga: [docs/mechanics/language.md](../mechanics/language.md).

## Peças

| Arquivo | Papel |
| --- | --- |
| `lib/i18n.ts` | Idioma atual (guardado no navegador), `t`, `tx`, `msg`, `useT`, `useLocale`, `setLocale`, lista `LOCALES` |
| `components/language-select.tsx` | Linha **Idioma** das Preferências e das Camadas do Pátio |
| `lib/locales/messages/<área>.json` | Fonte das traduções: cada texto do código com os 8 idiomas |
| `lib/locales/generated/<idioma>.json` | Gerado por `npm run i18n:build`; um catálogo por idioma, carregado sob demanda. Não editar à mão |
| `scripts/i18n-build.mjs` | Valida e gera. `--check` (testes), `--missing --only <pastas>` lista o que falta traduzir |
| `tests/i18n.cases.cjs` | `npm run test:i18n` |

## Como escrever um texto novo

A chave é o próprio texto, no idioma em que está escrito no código (português ou inglês). Nada muda no texto-fonte: só passa a ser envolvido.

- Componente React: `const t = useT()` e `{t("Preferências")}`, `title={t("Fechar")}`. Todo componente que mostra texto traduzido chama `useT()` (ou `useLocale()`), mesmo quando o texto vem de uma função de `lib/`, para redesenhar ao trocar o idioma.
- Fora do React (desenho no canvas, funções de `lib/`): `import { t } from "@/lib/i18n"` e `t("…")` lê o idioma atual. O canvas redesenha a cada quadro e já acompanha a troca. Se o nome `t` já existir no arquivo, importe `t as tr` e use `tr("…")`.
- Valores no meio: `t("Limitar a {n} FPS", { n: 30 })`. Os mesmos `{nomes}` aparecem em todas as traduções.
- Elementos no meio da frase (JSX): `t.x("Aperte {key} para entrar", { key: <kbd>E</kbd> })` (ou `tx(...)` fora do hook).
- Texto guardado como dado (tabelas de opções, nomes de itens, rótulos de parâmetros): marque na definição com `msg("Pulo")` e traduza onde aparece, `t(item.label)`. O valor guardado, comparado ou salvo continua o texto-fonte; só a exibição traduz.
- O script só enxerga chaves literais em `t(`, `tr(`, `tx(`, `t.x(` e `msg(`. Um texto passado como prop literal (`<Row label="Pulo" />`) deve ser traduzido no lugar onde está escrito: `label={t("Pulo")}`.
- Cada chave tem, no JSON da área, os 8 idiomas, inclusive o idioma de origem (igual à chave):
  `"Pulo": { "pt": "Pulo", "en": "Jump", "es": "Salto", "zh": "跳跃", "hi": "कूद", "ja": "ジャンプ", "ru": "Прыжок", "fr": "Saut" }`
- Depois de editar um JSON: `npm run i18n:build` e `npm run test:i18n`. Uma chave sem entrada aparece no idioma-fonte (nada quebra), mas o teste falha; uma entrada sem uso no código também.

## O que não é traduzido

Nomes próprios (cidades, gêneros e estilos musicais, kits, nomes científicos de aves, nomes de notas e acordes), o histórico de versões (`lib/changelog*.ts`), as páginas legais (`app/(legal)`), o painel e as ferramentas de admin (`app/admin`, `components/admin`, `lib/admin`, `app/map-editor`), mensagens de console/log e textos enviados ao servidor.
